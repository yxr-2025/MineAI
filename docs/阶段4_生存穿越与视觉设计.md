## 2. 穿越（第 1 项）

新增 `movement/NpcTraversal`：水、岩浆、梯子、门/栅栏门的分类。

`AStarPathPlanner.canStand` 现在接受三类节点：

- 陆地：脚/头为空气且下方实体。
- 游泳：脚部为水且身体空间非固体（水节点代价 ×1.6，优先走陆地）。
- 攀爬：脚或头为梯子/藤蔓/脚手架。

闭合的门在寻路中被视为可通行（因为可以打开），对角移动仍禁止切角。

`NpcLocomotion` 新增：

- **开门**：包围盒前方检测到门/栅栏门时调用 `DoorBlock.setOpen(...)` 打开。
- **跨越**：开启的门方块仍有碰撞，0.6 宽的躯体挤不过去；贴门时把 NPC 直接移到门另一侧的可站立点。
- **梯子**：目标在上方时以 `CLIMB_SPEED` 上爬，反之下降。
- **游泳**：水中关闭重力，目标在上方时上浮，否则缓慢下沉；空闲时也保持轻微下沉而非重摔。

**实机发现的关键问题**：跨越门后路径索引与几何位置不再匹配，NPC 会卡死。修复方式是跨越后调用 `PathMover.replan` 从当前位置重新寻路。

验证：用石头把门封成唯一通道，NPC 从 x=0.5 走到 x=6.2，门状态变为 `open=true`，`MoveAction` 返回 `SUCCESS`。

## 3. 生存行为（第 2 项）

| 工具 | 说明 |
| --- | --- |
| `eat` | 选背包中营养最高的食物并进食 |
| `attack` | 攻击范围内最近的生物，可按类型过滤，永不攻击玩家 |
| `flee` | 远离最近的威胁到指定距离 |

`EatAction` 先走原版使用路径；由于服务器端假玩家的物品使用 tick 不可靠，45 tick 后回退为直接结算食物属性，保证行为一定生效。

**死亡救援**：假玩家没有客户端，原版死亡/重生流程会把它永久留在死亡状态（且 `PlayerList.respawn` 会新建普通 `ServerPlayer`，丢失 agent 状态）。因此在 `MineAiMod` 订阅 `LivingDeathEvent`，对 `AgentPlayer` 取消死亡并原地恢复满血、食物与清除负面效果。

验证：

- 攻击：召唤僵尸 → 模型自主攻击、追击并确认击杀（`execute if entity` 无僵尸）。
- 进食：`/npc debug food 6` 后进食，食物 6 → 20。
- 救援：日志出现 `agent npc_1 was rescued from death`。

新增调试命令 `/npc debug food <0-20>` 与 `/npc debug health <amount>`，以及 `/npc debug goto <x> <y> <z>`（不依赖 LLM 直接验证移动）。

## 4. 工作台校验（第 3 项）

`craft` 现在会检查配方形状：

- `ShapedRecipe` 且宽或高 > 2 → 需要 5 格内存在工作台，否则返回
  `this recipe needs a crafting table within 5 blocks; none found`。
- 2x2 配方与无序配方仍可在背包完成。

验证：无工作台时返回上述错误；放置工作台后 `crafted 1 minecraft:wooden_pickaxe`。

## 5. 参数化技能（第 4 项）

`Skill` 增加 `originX/Y/Z`（记录轨迹开始时的 NPC 位置）。新增 `SkillRunner` 与 `run_skill` 工具：

- 按 `anchor - origin` 平移技能中所有坐标后重新入队动作。
- 只重放会改变世界或移动的步骤（`goto` / `mine` / `place` / `use` / `eat`），跳过只读、记忆与容器步骤。

验证：技能 `Mine the grass block at 12,-61,0 ...`（原点 5,-60,0）在锚点 18,-60,0 重放，正确挖掉平移后的 `25,-61,0`，日志为 `replaying 2 steps of skill ...`。

## 6. 多 NPC 与限流（第 5 项）

- `AgentPlayerManager` 增加选中目标：`/npc agent select <id>`，所有 agent 命令作用于选中 NPC，缺省回落第一个。
- 新增 `llm/RateLimitedProvider` 装饰真实 provider：信号量限制并发数，`synchronized` 节流保证请求启动最小间隔。

配置新增：

```json
"max_concurrent_requests": 2,
"min_request_interval_ms": 1000
```

验证：两个 NPC 并行推进各自目标，日志时间戳显示请求按 ≥1 秒间隔交错。

## 7. 视觉（第 6 项）

`state/VisionRenderer` 用 `BlockState.getMapColor` 把地形渲染成俯视 PNG（兼容模组方块），红色方块标记 agent，北在上。`screenshot` 工具把 PNG 以 base64 返回；`AgentController` 在工具消息之后追加一条 OpenAI `image_url` 格式的图像消息。

验证：模型调用 `screenshot` 后准确描述出「平坦草原、高度无变化、无树木水体、晴天早晨」，与实际世界一致。

## 10. 已知限制

- 游泳只支持上浮/下沉，没有真正的划水速度与氧气处理；水下寻路代价较高但仍可能选错。
- 梯子攀爬依赖目标 Y 差，横向进入梯子列需要寻路先给出对应节点。
- `attack` 每次只打一下，没有攻击冷却与武器选择策略。
- 技能只重放动作类步骤，容器/合成步骤被跳过；锚点必须是 NPC 脚部坐标（y 偏移会整体平移）。
- 限流是进程内的，多服务器实例之间不共享配额。
- 视觉是俯视色块图，不是第一人称画面，无法判断朝向或近距离细节。
- 平坦草原上放置的泥土仍会被草地随机刻覆盖，验收需即时检查。
- 中转站偶发连接超时，会让当次决策直接 `FAILED`，尚无自动重试。
