## 2. 自驱生命循环（第 1 项）

`/npc agent live` 启动后不再需要任何人工目标。

`AgentNeeds` 提供需求快照（信息，不是决策）：食物、生命、氧气、附近敌对生物数与最近距离、掉落物数、村民数、是否持有食物/工具、空手、空槽位、是否夜晚、是否下雨、维度。

`AgentController` 新增生命循环模式：

```text
startLifeLoop
  -> requestPlanning（规划器读取 needs + lessons + 上次结果）
  -> set_plan(steps) -> 逐步执行
  -> 每步结束 -> requestReflection -> 记录 lesson
  -> 计划走完 或 失败 -> 重新规划
  -> 规划器调用 mission_complete -> 进入 IDLE
  -> 空闲 30 秒后再次 requestPlanning
```

代码只负责"何时该想"（空闲计时、计划推进）与"如何落地"；"该做什么"完全由模型决定。

## 3. 反思与学习（第 2 项）

目标结束时（仅自主模式）发起一次反思调用，使用 `record_lesson(lesson, success)` 工具：

- `lesson` 写入 `AgentMemory.lessons` 并持久化到 `config/mineai/memory/<npcId>.json`。
- `success` 决定后续：成功推进到下一步；失败则触发重新规划。

`lessons` 与 `notes`、`skills` 一起注入系统提示词与规划提示词，因此下一轮决策能看到上次的教训。

实机证据（平坦无树世界）：

```text
[mineai] agent npc_1 lesson (failure): The spawn biome was an enormous treeless flat
grassland, and exploring in straight lines wasted all 100 steps (still no logs collected).
Next time, do wider-radius reconnaissance early and travel systematically (spiral/grid)
to locate a forested biome instead of pushing one direction repeatedly.
[mineai] agent npc_1 re-planning after failure
```

## 4. 多层规划（第 3 项）

规划器工具从 `set_goal` 改为 `set_plan(steps: string[])`：

- 一次给出有序的多步子目标（上限 `max_goals`，默认 8）。
- 控制器保存 `plan` 与 `planIndex`，逐步执行。
- 单步失败 → 反思后重新规划（模型能看到上次结果与教训，据此修订计划）。
- 计划走完 → 生命循环则回到空闲，mission 模式则结束。

实机证据：`new plan with 5 step(s)` → `plan step 1/5: Gather wood from nearby trees by hand to collect logs`。

## 5. 结构感知（第 4 项）

- `StructureScanner` 识别并返回结构特征列表：容器（含已用槽位/总槽位）、工作台、熔炉、门、床、耕地、刷怪笼、水、岩浆、光源、铁砧、钟。结果并入 `scan_area` 的 `features`。
- `read_sign(x,y,z)` 读取告示牌正面与背面文字。
- `collect_state` 的 `nearby_entities` 增加 `id`（供交易/攻击引用）、`distance`，以及对村民额外给出 `profession` / `trade_level` / `offers` 数量。

## 6. 社会经济（第 5 项）

| 工具 | 说明 |
| --- | --- |
| `say(message)` | 以 NPC 身份广播聊天消息 |
| `list_trades(entity_id)` | 列出村民职业、等级与全部报价（成本、产物、已用/上限、是否缺货） |
| `trade(entity_id, offer_index, count)` | 校验材料后执行交易，消耗成本、产出结果、增加使用次数 |

交易直接操作 `MerchantOffer`（`getCostA/B`、`getResult`、`increaseUses`、`notifyTrade`），不走 GUI。

实机证据：

```text
tool list_trades -> listed 2 offers
tool trade -> traded 1 time(s), received minecraft:pumpkin_pie x4
```

背包核验：绿宝石 16 → 15，新增 4 个南瓜派。

## 8. 关于第一人称视觉（未做）

按《设计原则：模型优先》的边界，这属于"感知通道"而非"决策轮子"，但优先级低于其余五项：

- 服务端没有渲染器，第一人称画面需要自建体素渲染或改客户端模组，成本远高于收益。
- 对执行任务而言，结构化查询（`query_block` / `scan_area` / `collect_state`）比图像更精确。
- 已有的俯视色块图已能表达布局，配合 `StructureScanner` 的语义特征足够当前工具集使用。

结论：保留为可选增强，不在本阶段实现。

## 10. 已知限制

- 生命循环的空闲判定是固定 30 秒，不随需求紧迫度变化。
- 反思是"每目标一次"的固定触发，没有"同类失败累积到阈值才反思"的机制。
- 计划只有一层，步骤之间没有显式依赖与前置条件。
- `StructureScanner` 只识别固定类别，不识别模组方块或自定义结构。
- 交易不校验村民的 `notifyTrade` 经验与补货逻辑，长期连续交易可能偏离原版。
- 尚无跨 NPC 的协作或信息共享。
- 中转站偶发连接超时；已有退避重试，但连续失败仍会结束当前轮。

## 11. 后续可选方向

1. 需求紧迫度驱动空闲间隔（越饿越频繁评估）。
2. 失败计数与"重复失败才反思"的节流。
3. 计划步骤的依赖图与前置校验。
4. 跨 NPC 共享黑板（协作/分工）。
5. 第一人称或等距渲染（若确有定性判断需求）。
