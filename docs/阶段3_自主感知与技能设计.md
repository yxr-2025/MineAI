## 2. 感知（第 5 项）

`TerrainScanner` 生成紧凑的俯视地图，避免把上千个方块塞进提示词：

- `surface`：每列最高非空气方块，单字符编码。
- `height`：每列地表相对高度，base36 编码。
- `legend`：字符 → 注册表 ID 的动态映射（兼容模组方块）。
- 行方向为 z（北在上），列方向为 x（西在左）。

两种使用方式：

- 系统提示词内置半径 4 的摘要，模型始终知道脚下是否平坦。
- `scan_area(radius)` 工具按需获取半径最大 12 的细节。

## 3. 移动（第 2 项）

### 3.1 分层

```text
NpcLocomotion   # 每 tick 的移动原语（碰撞、跳跃、滑墙、重力、朝向）
AStarPathPlanner# 有界 A*，输出站立点列表
PathMover       # 跟随路径；无解时退化为直线
```

`NpcMover.moveTo` 现在接收 NPC，因为寻路需要世界与起点：

```java
void moveTo(AgentPlayer npc, Vec3 target, double speed);
```

### 3.2 A* 细节

- 节点是「可站立点」：脚部与头部为空气、下方为实体、无液体。
- 邻居：四方向、对角（禁止切角）、上一格（跳）、下落最多 3 格。
- 启发式：八向距离 + 垂直惩罚。
- 上限：6000 节点、64 格距离，保证能在单个服务器 tick 内完成。
- `resolveGoal` 会把模型给的方块坐标解析成附近可站立点。

### 3.3 两个实机修复（重要）

**障碍检测必须用包围盒，不能用单点。** 玩家宽约 0.6，走到 x=5.7 时探测点 `floor(5.7+0.2)=5` 仍落在上一格空气，导致永远不触发跳跃、卡在方块旁。改为把包围盒按移动向量平移后检测脚/头两层。

**着地判定必须比较「脚底与方块顶面距离」。** 仅判断「下方是实体」会让 NPC 在跳跃后悬停——身体已高出一整格，脚下方块仍是实体。改为 `|y - (blockY+1)| < 0.08`，并新增每 tick 的空闲重力 `settle()`，使动作结束后 NPC 会落回地面。

### 3.4 渐进挖掘与工具选择

`ProgressiveMineAction`：

- 每 tick 用 `BlockState.getDestroyProgress` 累积进度。
- 通过 `Level.destroyBlockProgress` 广播破坏动画（其他客户端可见）。
- 进度到 1 时调用 `gameMode.destroyBlock` 结算掉落与耐久。
- 超时 1200 tick；取消/完成时发送 -1 清除动画。

`ToolSelector` 扫描快捷栏，选择 `ItemStack.getDestroySpeed` 最高的工具并切换选中槽。实机验证：木镐挖掘石头后耐久 `Damage: 1`。

动作现在可声明自己的超时（`Action.timeoutTicks()`），队列优先使用它，避免长动作被默认 400 tick 截断。

## 4. 容器与合成（第 3 项）

四个新工具：

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `list_container` | x, y, z | 经 `MachineAdapterRegistry` 返回槽位布局与内容 |
| `insert_item` | x, y, z, slot, item, count | 从背包取物品放入容器槽 |
| `extract_item` | x, y, z, slot, count | 从容器取物品放入背包 |
| `craft` | item, count | 按产物解析原版 `RecipeType.CRAFTING` 配方 |

同时修正了 `VanillaContainerAdapter` 的语义缺陷：

- 原 `extract` 把取出的物品直接丢弃；现在放入 NPC 背包，背包满则放回容器。
- 原 `insert` 会覆盖槽位内容；现在要求槽位为空或同物品且有足够空间，否则失败并把物品还给背包。

## 5. 记忆与技能（第 1、4 项）

### 5.1 AgentMemory

按 NPC 持久化到 `config/mineai/memory/<npcId>.json`：

- `notes`：`remember` 工具写入的长期事实。
- `skills`：命名技能（目标 + 工具调用序列 + 使用次数）。
- `history`：最近 60 条对话（仅用于审计/落盘）。

**关键修正**：`start` 时会清空对话历史，只保留 notes 与 skills。实机发现跨会话恢复完整历史会让模型直接复读上一轮的「Mission complete」，第一步就结束、完全不行动。

### 5.2 技能

- 目标成功结束时自动保存技能（步骤数 ≥ 2 且同名不存在）。
- `save_skill(name, description)` 显式保存当前轨迹。
- `recall_skill(name)` 返回技能步骤供模型改编。
- 系统提示词列出所有技能摘要，模型可自行决定是否复用。

### 5.3 自我验证

记录「最近一次世界修改是否已被读取验证」：

- 修改类工具（`mine` / `place` / `use` / `insert_item` / `extract_item` / `craft`）置位待验证。
- 读取类工具（`query_block` / `collect_state` / `scan_area` / `list_container`）清除待验证。
- 模型在待验证状态下直接给出最终答复时，注入一条系统提示要求先验证，最多两次。

## 6. 自主循环（第 1 项）

`/npc agent mission <长期目标>` 进入自主模式：

```text
startMission
  -> PLANNING：用 set_goal / mission_complete 工具让模型给出下一个子目标
  -> 子目标执行（完整决策循环）
  -> 子目标完成 -> 再次 PLANNING
  -> mission_complete 或达到 max_goals -> FINISHED
```

- 子目标之间有 40 tick 冷却，避免连续轰炸 API。
- `max_goals`（配置项，默认 20）限制失控。
- 规划调用使用独立的提示词，包含 mission、已完成子目标数、当前状态、notes 与 skills。

## 7. 配置与命令

`config/mineai/llm.json` 新增 `max_goals`：

```json
{
  "enabled": true,
  "provider": "deepseek",
  "base_url": "https://tokeness.ai/v1",
  "model": "deepseek-v4-flash",
  "timeout_seconds": 90,
  "max_steps": 16,
  "max_goals": 20
}
```

命令：

| 命令 | 说明 |
| --- | --- |
| `/npc agent start <目标>` | 单目标 |
| `/npc agent mission <长期目标>` | 自主 mission 模式 |
| `/npc agent stop` | 停止 |
| `/npc agent status` | state / step / goal / last / error |
| `/npc agent memory` | 列出 notes 与 skills |
| `/npc agent forget` | 清空该 NPC 记忆 |

## 9. 实机验证（真实 LLM）

### 9.1 合成 + 容器全链路

场景：放置箱子、`/give` 4 个橡木原木。
目标：`Craft oak planks ... then put all the planks into the chest at 3,-60,0.`

```text
step 1  craft            -> 4 次合成，得到 16 木板
step 2  collect_state + scan_area
step 3  list_container   -> 确认箱子为空
step 4  insert_item      -> 放入 16 个木板
step 5  list_container   -> 自检
step 6  无 tool_calls -> FINISHED
```

核验：`data get block 3 -60 0 Items` → `{Slot:0b, id:"minecraft:oak_planks", Count:16b}`。

### 9.2 自主 mission

场景：箱子在 (3,-60,0)。
mission：`Gather 4 dirt blocks from the ground and store all of them in the chest ...`

```text
planning -> 模型自行提出子目标：Walk to the chest at 3,-60,0 and deposit at least 4 dirt blocks into it.
子目标执行 -> 走路 + insert_item + list_container 自检
planning -> mission_complete
```

核验：箱子 `{Slot:0b, id:"minecraft:dirt", Count:4b}`。

### 9.3 渐进挖掘 + 工具选择

场景：`/setblock 3 -60 1 minecraft:stone`，把木镐放进 hotbar.5。
目标：`Mine the stone block at 3,-60,1.`
结果：`ProgressiveMineAction(3,-60,1) SUCCESS`，方块变为空气，木镐 `Damage: 1`。

### 9.4 寻路与台阶

- 平地 12 格：`MoveAction(12.5,-60.0,0.5) SUCCESS`。
- 走上一格高的石头：修复包围盒检测后 `MoveAction(6.5,-59.0,0.5) SUCCESS`，NPC 停在 `y=-59.0`。

### 9.5 记忆持久化

重启服务器后重新 `npc spawn`，`/npc agent memory` 仍返回 3 个技能；对话历史不再恢复（已修正）。

### 9.6 端到端回归

目标：`Walk to 10,-61,5, then mine the ground block at 10,-61,6, then walk back to 0,-61,0.`

```text
MoveAction(10.5,-59.0,5.5)          SUCCESS
ProgressiveMineAction(10,-61,6)     SUCCESS
MoveAction(0.5,-60.0,0.5)           SUCCESS
最终坐标 0.7,-60.0,0.5
```

## 10. 已知限制

- 寻路不支持游泳、爬梯、开门、跨维度；水下与复杂地形会失败。
- 没有战斗、进食、逃跑等生存行为（`health` / `food` 已采集但无对应工具）。
- `craft` 不要求工作台，只要材料在背包即可；未处理需要工作台的 3x3 专有配方差异。
- 技能只是「调用序列 + 文本描述」，不是可参数化执行的程序，复用依赖模型改编。
- 单 NPC，无限流；多 NPC 会并发请求同一 API。
- 视觉（截图）未实现：地形摘要已足够覆盖当前工具集，接入图像模型属于后续独立工作。
- 放置的方块在平坦草原会被草地随机刻覆盖，验收需即时检查。
